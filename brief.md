# Nimble Links for WordPress — Plugin Plan

## Overview

A WordPress plugin that connects to a user's Nimble Links account via API token, automatically creates short links for published posts, and provides a Gutenberg sidebar panel with the short URL (copy button) and QR code (download button).

## Plugin Metadata

- **Plugin Name:** Nimble Links
- **Slug:** nimble-links
- **Minimum PHP:** 7.4
- **Minimum WordPress:** 6.0
- **Tested Up To:** 6.7
- **License:** GPLv2

## Nimble Links API Reference

The plugin communicates with the Nimble Links API. The base URL should default to `https://nimblelinks.com/api/v1.0` but be filterable so users with custom deployments can override it.

All requests require an `Authorization: Bearer {token}` header, plus `Content-Type: application/json` and `Accept: application/json`.

### `GET /me` — Validate Token & Get Account Info

**Response (200):**
```json
{
    "email": "user@example.com",
    "team": {
        "id": "uuid-string",
        "name": "My Team"
    }
}
```

**Response (401):** Invalid or expired token.

### `POST /links` — Create a Short Link

**Request body:**
```json
{
    "type": "short-link",
    "title": "My Blog Post",
    "destination": "https://example.com/my-blog-post"
}
```

- `type` (string, required): Always `"short-link"` for this plugin.
- `title` (string, optional): Max 100 characters.
- `destination` (string, required): Must be a valid URL.

**Response (201):**
```json
{
    "data": {
        "id": "aBc123",
        "title": "My Blog Post",
        "type": "short-link",
        "url": "https://nimblelinks.com/aBc123",
        "created_at": "2026-04-10T12:00:00Z",
        "updated_at": "2026-04-10T12:00:00Z"
    }
}
```

The `id` field is the link slug used in subsequent API calls. The `url` field is the full short URL to display to the user.

**Response (422):** Validation errors (invalid URL, etc):
```json
{
    "message": "...",
    "errors": { "destination": ["The destination must be a valid URL."] }
}
```

### `GET /links/{id}/qr` — Get QR Code URLs

**Response (200):**
```json
{
    "svg": "https://nimblelinks.com/qr/aBc123?format=svg",
    "png": "https://nimblelinks.com/qr/aBc123?format=png"
}
```

These are publicly accessible URLs that render the QR code pointing to the short link. They can be used directly in `<img>` tags or downloaded.

### Rate Limits

30 requests per minute, 300 per hour, per team. The plugin should not hit these under normal usage (one link created per post publish).

## Feature 1: Settings Page

### Location

Settings → Nimble Links (`/wp-admin/options-general.php?page=nimble-links`)

### Options (stored in `wp_options`)

| Option Key | Type | Default | Description |
|---|---|---|---|
| `nimble_links_api_token` | string | `''` | API bearer token |
| `nimble_links_team_name` | string | `''` | Cached team name from validation |
| `nimble_links_auto_short_link` | bool | `true` | Auto-create short link on publish |
| `nimble_links_auto_qr_code` | bool | `true` | Auto-fetch QR code on publish |

### UI

**Disconnected state:**
- API Token input field (password type, pasted by user)
- "Connect" button that validates via `GET /me`
- Helper text: "Find your API token at nimblelinks.com → Team Settings → API Tokens"
- On success: store token + team name, show connected state
- On failure: inline error — "Invalid token" or "Could not connect to Nimble Links"

**Connected state:**
- Status line: "Connected to **[Team Name]**" with a green dot
- "Disconnect" button (clears token + team name)
- Checkbox: "Automatically create a short link for new posts" (default: on)
- Checkbox: "Automatically generate a QR code for new posts" (default: on)

### Token Encryption

The API token must be encrypted at rest in `wp_options`. Use PHP's `sodium_crypto_secretbox` (bundled since PHP 7.2, and WordPress ships a sodium_compat polyfill as a fallback).

- **Encryption key:** Derive from WordPress's `AUTH_KEY` salt (defined in `wp-config.php`, unique per installation). Hash it to the required 32-byte key length: `sodium_crypto_generichash(AUTH_KEY, '', SODIUM_CRYPTO_SECRETBOX_KEYBYTES)`.
- **Encrypt:** `sodium_crypto_secretbox($token, $nonce, $key)` — generate a random nonce per encryption, prepend it to the ciphertext, then base64-encode the whole thing for storage.
- **Decrypt:** Base64-decode, extract the nonce (first `SODIUM_CRYPTO_SECRETBOX_NONCEBYTES` bytes), decrypt with the same derived key.
- **Helper methods:** Add `encrypt(string $plaintext): string` and `decrypt(string $encrypted): string` static methods to a small `src/Encryption.php` class. The settings page and API client both use these.
- **Sanitize callback:** When saving the token, encrypt it before it hits the database. When reading it for API calls, decrypt it first.

### Implementation Notes

- Register via `add_options_page()` in `admin_menu` hook
- Use WordPress Settings API (`register_setting`, `add_settings_section`, `add_settings_field`)
- Token validation on "Connect" is an AJAX call (`wp_ajax_nimble_links_validate_token`) that hits `GET /me` server-side and returns the team name or error
- Sanitize callback strips whitespace from token, then encrypts before saving
- Register a `plugin_action_links` filter to add a "Settings" link on the Plugins list page

## Feature 2: Auto Short Link on Publish

### Trigger

Hook into `transition_post_status` — fire when a post's status transitions to `publish` and the post type is `post`.

### Conditions (all must be true)

- API token is configured
- `nimble_links_auto_short_link` option is enabled
- Post type is `post`
- Post doesn't already have a `_nimble_links_id` in post meta

### Flow

1. Post transitions to `publish`
2. Check all conditions above
3. Call `POST /links` with `type: "short-link"`, `title: {post title}`, `destination: {permalink}`
4. Store `_nimble_links_id` and `_nimble_links_url` in post meta
5. If `nimble_links_auto_qr_code` option is enabled, call `GET /links/{id}/qr`
6. Store `_nimble_links_qr_svg` and `_nimble_links_qr_png` in post meta

### Post Meta

| Meta Key | Value |
|---|---|
| `_nimble_links_id` | Link slug from API (`data.id`) |
| `_nimble_links_url` | Full short URL (`data.url`) |
| `_nimble_links_qr_svg` | QR code SVG URL |
| `_nimble_links_qr_png` | QR code PNG URL |

All prefixed with `_` so they're hidden from the custom fields UI.

### Error Handling

- If the API call fails for any reason: do NOT block the publish. Log via `error_log()`. The user can manually generate from the sidebar.
- If the token is invalid (401): set a transient to show an admin notice on the next page load: "Nimble Links: your API token is no longer valid. Please reconnect in Settings → Nimble Links."

## Feature 3: Gutenberg Sidebar Panel

### Registration

- Register as a `PluginSidebar` using `@wordpress/plugins` and `@wordpress/edit-post`
- Icon: use the `link` icon from `@wordpress/icons`
- Title: "Nimble Links"
- Only render content when editing a `post` post type

### Panel States

**State A — Not connected:**
- Message: "Connect your Nimble Links account to generate short links and QR codes."
- Link to the settings page

**State B — Connected, no short link yet:**
- "Generate Short Link" button
- On click: call `POST /wp-json/nimble-links/v1/links` with `{ post_id }`
- Show a spinner while the request is in flight

**State C — Connected, short link exists:**

Short Link section:
- Read-only text input showing the short URL
- "Copy" button → copies to clipboard, text changes to "Copied!" for 2 seconds

QR Code section (only if QR URLs exist in post meta):
- QR code image rendered from the SVG URL
- "Download PNG" button → triggers a file download of the PNG URL
- "Download SVG" button → triggers a file download of the SVG URL

### Internal WP REST Endpoints

The sidebar JS must NOT call the Nimble Links API directly (that would expose the token to the browser). Instead, register internal WP REST routes that proxy through the server:

```
POST /wp-json/nimble-links/v1/links
    Body: { "post_id": 123 }
    Permission: current_user_can('edit_post', post_id)
    Action: Creates short link + QR via Nimble Links API, stores post meta
    Returns: { "url": "...", "qr_svg": "...", "qr_png": "..." }

GET /wp-json/nimble-links/v1/links/{post_id}
    Permission: current_user_can('edit_post', post_id)
    Action: Returns stored link data from post meta
    Returns: { "url": "...", "qr_svg": "...", "qr_png": "..." } or 404 if none
```

### Sidebar Data Loading

On sidebar mount:
1. Call `GET /wp-json/nimble-links/v1/links/{post_id}` to check for existing link data
2. If data exists → render State C
3. If 404 → render State B

Use local React state (`useState`/`useEffect`) for managing the sidebar — no need for a WordPress data store for this scope.

### Build Tooling

- Use `@wordpress/scripts` for building (`npm init`, `npm install @wordpress/scripts --save-dev`)
- Source: `js/sidebar/index.js` → Build: `build/index.js`
- Enqueue via `enqueue_block_editor_assets` hook
- Pass config to JS via `wp_localize_script`:
    - `nimbleLinks.restUrl` — `rest_url('nimble-links/v1')`
    - `nimbleLinks.nonce` — `wp_create_nonce('wp_rest')`
    - `nimbleLinks.isConnected` — boolean, whether token is configured
    - `nimbleLinks.settingsUrl` — `admin_url('options-general.php?page=nimble-links')`

## API Client (`src/Api/Client.php`)

Thin wrapper around WordPress HTTP API:

```php
class Client
{
    private string $token;
    private string $baseUrl;

    public function __construct(string $token, string $baseUrl = 'https://nimblelinks.com/api/v1.0')

    public function me(): array|WP_Error
    public function createLink(string $title, string $destination): array|WP_Error
    public function getQr(string $linkId): array|WP_Error
}
```

- Returns parsed JSON array on success, `WP_Error` on failure
- Uses `wp_remote_get` / `wp_remote_post` (WordPress HTTP API)
- Sets `Authorization: Bearer {token}`, `Content-Type: application/json`, `Accept: application/json`
- Timeout: 15 seconds
- User-Agent: `NimbleLinksWP/{plugin_version}`
- Base URL is filterable: `apply_filters('nimble_links_api_base_url', $baseUrl)`

## Uninstall

`uninstall.php` runs when the plugin is deleted (not just deactivated):

- Delete options: `nimble_links_api_token`, `nimble_links_team_name`, `nimble_links_auto_short_link`, `nimble_links_auto_qr_code`
- Leave `_nimble_links_*` post meta in place (the short links still work, and cleaning up across all posts is expensive for no benefit)

---

## Security

- API token encrypted at rest in `wp_options` via sodium, never sent to the browser
- Sidebar JS calls internal WP REST endpoints (with nonce auth), which call Nimble Links server-side
- WP REST endpoints check `current_user_can('edit_post', $post_id)` before any action
- Sanitize and escape all output (`esc_url`, `esc_html`, `esc_attr`)

## Out of Scope (v2)

These are intentionally deferred to keep v1 simple:

- Classic editor (non-Gutenberg) meta box
- Click count / analytics display in the sidebar
- Configurable post types (currently hardcoded to `post`)
- Link deletion from within WordPress
- Bulk generation for existing posts
- Custom domain selection when creating links

## Implementation Order

1. **Scaffold** — Plugin entry file (`nimble-links.php`), PSR-4 autoloading via Composer or manual `require`, activation/deactivation hooks
2. **API Client** — `Client.php` with `me()` method only
3. **Settings Page** — Token input, AJAX validation, connect/disconnect, auto-generation checkboxes
4. **PostHandler** — `transition_post_status` hook, create link on publish, store post meta
5. **WP REST Endpoints** — `LinksController.php` with POST and GET routes
6. **Gutenberg Sidebar** — `@wordpress/scripts` setup, React components, copy/download interactions
7. **Polish** — Admin notices for invalid tokens, plugin action links, `readme.txt`
